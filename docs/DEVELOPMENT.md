# Maintaining the template

The template is ready to copy into a new project. It contains instructions, five optional profiles, eight blank content templates, a review-report template, a fictional example, and a Python helper. It does not contain a personal subject wiki.

## Architecture

AGENTS.md is the shared operating entry point; CLAUDE.md points to it. README.md describes actual usage. FORMAT.md defines the local contract and its relationship to OKF v0.2. WORKFLOWS.md separates capture, ingestion, retrieval, and review.

REVIEW.md describes an on-demand, report-only editorial pass, source-impact tracing, and claim-specific freshness. It does not add an automatic semantic checker, a scheduler, or a multi-agent requirement. Review-report templates and requested drafts go in private out/ directories outside the OKF bundle.

Scripts/wiki.py uses PyYAML's safe loader with duplicate-key rejection. Everything else uses Python's standard library. It never downloads, deletes files, performs AI inference, executes procedures, or evaluates models.

The helper reads current files rather than using a persistent database. Searches and record queries validate the corpus, including captured source hashes, before answering. This is suitable for modest collections; a large archive can make repeated validation expensive. Add a derived index only with explicit freshness and rebuild rules.

Examples are authored fictional content. Their directory indexes are generated by the helper. The preserved source's manifest hash is part of the fixture: if its bytes change, deliberately update the manifest and review all dependent example citations.

## Invariants

- Personal data and test outputs stay in .local. Never use a user's source as a public fixture.
- Canonical knowledge is authored in files. Derived indexes never acquire independent facts.
- Source bytes and versions are preserved; resource/capture associations are checked.
- Initialization and page creation refuse existing content. Index regeneration preflights every ownership marker before writing.
- Human-owned pages are unchanged by helper commands.
- Null, zero, numeric ranges, and inequalities retain distinct meanings.
- Exact filtering returns all matches in the recorded dataset and rejects invalid input rather than returning a partial answer.
- A review hash covers provenance metadata and body, not merely prose. Verification remains an actual source review, not a structural check.
- YAML custom executable tags and duplicate YAML/JSON keys are rejected.
- Local references and generated outputs cannot escape their declared vault paths.

## Validate changes

From the repository root:

~~~powershell
py -3 -m unittest discover -s tests -v
py -3 scripts/wiki.py --vault examples/vault check --strict
py -3 scripts/wiki.py --vault examples/vault find "routine persistence"
py -3 scripts/wiki.py --vault examples/vault records --metric membership --period 2025
git diff --check
~~~

When example metadata changes, rebuild its indexes and inspect the output:

~~~powershell
py -3 scripts/wiki.py --vault examples/vault index
~~~

Tests use private copies in .local/test-runs and leave them for inspection. They cover version retention, no overwrite, complete filters, invalid input, escaped paths, review invalidation, citation resolution, and preservation of human notes. They do not benchmark semantic retrieval or establish factual validity.

Inspect the rendered Markdown or open the example vault in Obsidian when changing links, footnotes, or reading structure. The checker verifies ordinary file references; complex Markdown constructs and heading anchors still need review.

## Extension points

Add profiles for domain rules, preserving the minimal shared contract. Update config choices when adding a supported profile. Add a page template only when it serves an independently useful retrieval or editing need.

A model's formula is documentation in this starter. A future calculator must validate inputs, units, universes, missingness, dependencies, assumptions, and supported operations. Do not evaluate arbitrary expressions from imported text.

For a search or database layer, keep a revision manifest and make it rebuildable. Define how file changes invalidate results. Do not require hosted infrastructure just to browse Markdown.

For public guides, use a deliberate content and field allowlist, with tests against private leakage. No export mechanism is implemented.

Keep these docs aligned with behavior. Subject-specific handoff state belongs in .local, while enduring operating rules belong in AGENTS.md and these contracts.
